Purpose and authority

This supplement records the factual delta between the report state labelled R13 and the repository snapshot that includes the Unified Operations Control Plane. It is an integration aid, not a replacement for the 379-page report and not evidence that staging or production were completed.

The supplied report presents the project as an experimental auditable platform and already distinguishes implementation, static verification, current result, historical execution, blocked attempt, reproduction and validation. The current repository extends that same evidence discipline to engineering operations.

Delta summary

The repository now contains server-side capability policies; the roles QA, Operations and ReleaseApprover; Mission Control, Quality Runs, Evidence Explorer, Deployments, Cloud Resources, Approvals and User/Role Administration; a closed operation catalog; operation records, confirmation and approval; GitHub workflow wrappers; and authenticated callback/artifact handling.

Architecture integration

The report architecture should now distinguish three planes:

  1. runtime/data processing;
  2. user and control APIs;
  3. engineering operations and evidence.

The browser remains outside the provider trust boundary. It selects a closed operation identifier; the backend authorises and records it; specialised runners hold the provider identity.

Roles and separation of powers

The current role model adds QA, Operations and ReleaseApprover. Admin manages application users and roles but does not automatically receive production deploy or destroy capability. The distinction remains meaningful even when one academic project owner holds several roles, because confirmation and approval steps remain separately recorded.

Quality and evidence

Quality and evidence operations are selected from a bounded catalog and dispatched to authoritative workflows. A provider success status is not enough for a PROVED claim. The expected artifacts, snapshot reference, environment, producer and SHA-256 must be present and the scope must match the claim.

Cloud and deployment

The implementation contains Terraform, GKE/Autopilot, Cloud Deploy, Artifact Registry, WIF and release/deployment workflows. The correct factual statement remains that the source implementation is advanced but the supplied artifacts do not prove a signed release for the final head, a qualified staging deployment or production.

Scientific and operational boundary

The current engineering progress does not change the report’s scientific limits. Candidate FWI, KBDI and NatureProtector calculations remain technical comparison components rather than official, calibrated or validated operational methods.
